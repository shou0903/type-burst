# TYPE BURST 行動分析仕様

## 目的

改善判断に必要な「どこから来て、どの画面を経て、どのモードを始め、完走し、次に何をしたか」を把握する。個々の打鍵を監視したり、プレイヤーの正確な成績を再現したりする目的では使用しない。

## 数え方

- **イベント数:** ボタン操作やゲーム完了など、定義済みの行動が発生した回数。
- **セッション数:** タブの`sessionStorage`に保存する短期ID単位。ストレージが使えない場合はページを開いている間のメモリID単位。
- **匿名プレイヤーID数:** 登録不要の共通playerIdをサーバーでHMAC変換した識別値単位。秘密鍵が設定された期間だけ算出する。
- **D1/D7/D30:** 初回観測日の1・7・30日後に観測された匿名プレイヤーIDの割合。人間、アカウント、世帯の人数ではない。

Vercel Analyticsのページビューと当サイトの日別集計は単位が異なるため、両者を合算して「ユーザー数」と呼ばない。

## 主要ファネル

1. `content_entry`: 流入元とページ種別を粗い分類で記録
2. `screen_view`: ホーム、ゲーム、結果、分析、ランキング、モバイル受け渡し
3. `game_start`: モード、難易度、入口、初回、デイリー順位対象、FOCUS
4. `game_finish` / `game_exit`: 自然終了か確認後の中断、成績は範囲のみ
5. `result_action`: 再挑戦、分析、ランキング、共有、タイトル
6. `share_action` / `ranking_action` / `analysis_action`: 次の行動と成否

補助イベントは`settings_change`、`transfer_action`、`mobile_handoff`、`tool_action`、`feature_used`、`flow_failure`。`tool_action`は速度測定・文章練習・苦手キー練習・数字記号練習・入力方式判定・作業時間換算・ローマ字入力ラボの開始／完了／実行だけを記録し、入力値や練習対象キーは送らない。`feature_used`は同じ機能を1プレイ中に何度使っても最大1回に抑える。

## 収集しないもの

- 実際の打鍵、入力途中の文字、出題語句、ブロックID
- ニックネーム、引き継ぎコード、共有ID
- 完全なURL、検索語、完全な参照URL、広告識別子
- 正確なスコア、KPM、正確率、連鎖数、時間、レベル
- 生のplayerId、生のIPアドレスを長期保存した値

成績は固定の低カーディナリティ区間へ変換する。クライアントとAPIの双方でイベント名・属性名・属性値を許可リスト検証し、未知の属性は破棄する。

## 保存と安全策

- クライアントは最大10件をまとめ、待ち行列は最大20件。5秒またはページ離脱時にベストエフォート送信する。
- 計測の失敗、オフライン、ストレージ拒否、API制限はゲームと結果画面を止めない。
- APIはJSON・同一オリジン・本文サイズ・イベント件数を検証し、IP・セッション・全体の回数上限を適用する。
- Redisには生イベントを保存せず、日別カウンターと期限付きの匿名集合だけを保存する。
- 日別カウンター400日、セッション・匿名集合120日、重複排除25時間、回数制限1時間を上限とする。
- `TELEMETRY_HASH_SECRET_V1`を設定しない環境では再訪率を無効表示にする。鍵更新時は`V2`を新しい書き込み先とし、`V1`は削除互換にだけ利用する。
- 設定で計測を停止できる。クラウド記録削除時は保持期間内のHMAC識別値も削除する。匿名の合計カウンターは個別に差し引けない。

## 運用時に見る指標

- 流入ページ・流入元別のゲーム開始率
- モード・難易度別の開始数、完了数、完了率、中断率
- チュートリアル完了率と初回ゲーム完了率
- 結果後の再挑戦率、分析閲覧率、共有率、ランキング送信成功率
- データ引き継ぎ成功率とフロー別エラー率
- 練習ツール別の利用数と開始から完了への推移
- 匿名プレイヤーID単位のD1/D7/D30（秘密鍵設定期間のみ）

母数が小さい区分で結論を急がず、変更前後は同じ定義・十分な期間で比較する。
